# Запуск и экспорт на телефоны — 2.3

## Текущий статус

В Linux с Godot **4.6.3 stable** собран настоящий APK **2.3.0 (5)** для Android 7.0+, ARM32/64. Подпись прежним сертификатом, ZIP CRC и 16 KB ZIP/ELF alignment проверены; точные параметры — [android-build.md](android-build.md). SDK и закрытый ключ в исходники не входят.

IPA **2.3.0 (5)** для физического iPhone arm64, iOS 14+ собрана на Mac, независимо проверена после скачивания и опубликована вместе с APK. [Проверка CI](ios-ci.md), [размеры, SHA-256 и постоянные ссылки](builds.md). AAB и Windows 2.3 не собирались; доступный Windows ZIP остаётся версией 2.2. Версия 2.3 на физических Android/iPhone ещё не проверена.

## Общие настройки

- Рекомендуемая версия редактора: Godot **4.6.3 stable**.
- Базовое разрешение: **1080 × 1920**, портретная ориентация.
- Рендерер: **Compatibility**, без требований к Vulkan.
- Идентификатор приложения: **`org.geckorush.game`**.
- В Godot откройте **Editor → Manage Export Templates** и установите шаблоны **точно той же версии**, что и редактор. Шаблоны 4.6, 4.6.2 и 4.6.3 не следует считать взаимозаменяемыми.
- Перед экспортом один раз откройте проект в редакторе и дождитесь импорта ресурсов.

Официальные инструкции: [Android](https://docs.godotengine.org/en/4.6/tutorials/export/exporting_for_android.html) и [iOS](https://docs.godotengine.org/en/4.6/tutorials/export/exporting_for_ios.html). Проверяйте версии SDK, NDK и Java по документации используемой версии Godot.

## Android: отладочный APK

1. На своей машине установите Android Studio или Android SDK Command-line Tools, Platform Tools и Build Tools. Пакеты платформы, Build Tools и NDK должны соответствовать требованиям Godot 4.6. Для обычного экспорта без пользовательских плагинов отдельный проект Android/Gradle создавать не нужно.
2. Установите поддерживаемый Godot JDK. Обычный выбор для Godot 4 — JDK 17; ориентируйтесь на раздел Java SDK в документации 4.6. Наличие только команды `java` не подтверждает наличие полного JDK.
3. В **Editor Settings → Export → Android** укажите **Java SDK Path** и **Android SDK Path**. Проверьте доступность `adb` и принятие лицензий Android SDK.
4. Откройте **Project → Export**, выберите пресет **Android**. Если редактор сообщает об отсутствующей опции из-за другой версии Godot, пересоздайте пресет Android и перенесите идентификатор `org.geckorush.game` и портретные настройки.
5. Для первой проверки выберите APK и **Export With Debug**. Настройте отладочный keystore средствами Godot/Android согласно документации. Отладочную сборку не используйте как магазинный релиз.
6. На телефоне включите параметры разработчика и отладку по USB. Убедитесь, что устройство разрешило подключение этого компьютера.

Пример команд после полной настройки SDK, шаблонов и пресета:

```sh
mkdir -p build/android
godot --headless --path . --export-debug "Android" build/android/gecko-rush-debug.apk
adb install -r build/android/gecko-rush-debug.apk
```

Установка с `-r` сохраняет данные при совместимой подписи. Если установленное приложение подписано другим ключом, Android может отказать в обновлении. Удаление приложения перед установкой сотрёт локальный прогресс.

## Android: подписанный релиз и AAB

Для релиза создайте собственный keystore и настройте подпись в пресете Android. Храните ключ и пароли вне репозитория; не добавляйте их в исходники, README или переписку. Сначала проверьте подписанный APK на устройстве.

Для Google Play выберите в пресете формат **AAB**, задайте актуальные `version/code` и `version/name`, затем экспортируйте релиз. Если используются Gradle-сборка или плагины, установите Android Build Template и необходимые версии Gradle/NDK по документации Godot.

```sh
godot --headless --path . --export-release "Android" build/android/gecko-rush.aab
```

Команда предполагает, что формат AAB уже выбран, каталог `build/android` существует и релизная подпись настроена. AAB не устанавливается напрямую через `adb install`; для проверки используйте внутреннее тестирование Google Play или подходящий процесс `bundletool`.

## iOS

Нативная сборка приложения выполняется через **macOS и Xcode**. В этом проекте сборку выполняет облачный Mac GitHub: собственный Mac для получения готовой IPA не требуется. Linux-редактор сам по себе не выполняет `xcodebuild`.

Готовый неподписанный файл можно подписать и установить **с Windows через Sideloadly**: подключите iPhone кабелем, подтвердите доверие компьютеру, выберите телефон, перетащите IPA, укажите Apple ID в программе и нажмите **Start**. При запросе подтвердите профиль разработчика и включите режим разработчика в настройках iPhone. Бесплатная подпись Apple ID действует **7 дней**; продлевайте её с тем же Apple ID, не удаляя игру. После установки игра работает на телефоне без ПК. Apple ID и коды подтверждения не нужны в GitHub Actions и не входят в исходники или IPA.

Для самостоятельной сборки на Mac:

1. На Mac установите Godot той же версии и его экспортные шаблоны, Xcode с инструментами командной строки и SDK iOS.
2. Откройте проект, затем **Project → Export → iOS**.
3. Укажите Bundle Identifier `org.geckorush.game`, Team ID, имя приложения и версию. Выберите используемую команду разработчика, настройте подпись и provisioning profile для способа распространения.
4. Экспортируйте проект iOS, откройте полученный проект в Xcode и проверьте **Signing & Capabilities**. Сначала запустите его на подключённом iPhone через Xcode.
5. Для распространения выполните **Product → Archive** и выберите соответствующий способ в Organizer: TestFlight/App Store или разрешённый вашей подписью способ установки.

Пресет не содержит Team ID, сертификатов, профилей подписи или секретов. Возможность бесплатного локального запуска и ограничения подписи определяются учётной записью Apple и Xcode; для TestFlight/App Store нужен соответствующий доступ Apple Developer.

## Ручная проверка на устройствах

Headless-тесты проверяют логику, а следующие сценарии нужно выполнять на настоящем телефоне:

- **Экран и safe area.** Проверить 9:16 и вытянутый экран, вырез/камеру, скругления и нижний индикатор жестов. Высота, баланс, пауза и кнопки должны быть видны и доступны; прокрутка профиля должна доходить до последнего пункта.
- **Сенсор.** Один тап вызывает один прыжок. Серия быстрых тапов и второй палец не создают прыжки в полёте. Нажатие паузы, кнопок меню и ежедневной награды не передаётся в игровое поле.
- **Жизненный цикл.** Свернуть игру во время бега и перелёта, заблокировать телефон, вернуться из переключателя приложений. Игра должна ждать продолжения. Затем принудительно закрыть приложение и проверить восстановление незавершённого забега.
- **Сохранения.** Завершить забег, записать баланс/XP/рекорд, перезапустить приложение. Проверить однократное начисление результатов, однократную ежедневную награду и смену дня по локальной дате устройства.
- **Игровой процесс.** Пройти начальный безопасный участок; проверить обе стены, центральные и движущиеся угрозы, столкновение, результаты и «Ещё раз». Монеты должны собираться один раз и давать видимый отклик.
- **Адаптация.** Переключить настройки размера интерфейса/шрифта ОС, если они влияют на приложение. Проверить, что игровое поле и кнопки не обрезаются и геккон остаётся маленьким.
- **Звук.** Отдельно выключить музыку и эффекты, перезапустить игру и проверить сохранение обоих переключателей. Проверить паузу и возвращение после звонка/другого аудиоприложения.
- **Производительность.** На обычном устройстве играть непрерывно не менее 10 минут: следить за FPS, временем кадра, нагревом и памятью через профайлер Godot/инструменты платформы. Цель 60 FPS требует фактического замера; наличие Compatibility-рендерера её не гарантирует.
- **Длительный прогресс.** Проверить открытие миров, смену темы, достижения, рост уровня и отсутствие повторного начисления наград при перезапуске приложения.

Результаты выполненных проверок следует сверять с [validation.md](validation.md). Не считайте этот список записью о пройденных тестах.


## Архив: проверенное окружение 2.2

На Linux с Godot 4.6.3 и OpenJDK 21 был собран APK 2.2.0; использовались официальные шаблоны, Android build-tools 36.0.0 и platform-tools 37.0.3. Подпись и выравнивание проверены. IPA 2.2.0 (4) была собрана на облачном Mac через Xcode для физического iPhone arm64/iOS 14+, ZIP, метаданные, исполняемый файл и PCK проверены. Подписи Apple не было; физические устройства не проверялись. Этот исторический результат не означает, что новый IPA 2.3 уже готов.
